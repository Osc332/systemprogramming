# Лабораторная работа 1. Процесс изнутри

## Среда выполнения
* **Операционная система:** Windows 11 (x64).
* **Компилятор:** Microsoft (R) C/C++ Optimizing Compiler версии 19.44.35219 для x64.
* **Инструменты мониторинга:** Process Explorer и Диспетчер задач Windows.

## Шаг 1. Запуск программы на C
* **Вывод программы (PID):** `agent v0, pid=20075`.
* **PID процесса:** `20075`.

## Шаг 2. Поиск процесса в мониторе
* **PID в мониторе:** `20075` — совпал с номером, который напечатала программа.
* **Занимаемая память (Working Set):** `0.3 мб`; в списке Process Explorer отображалось `3 546 кб`.

labs/01-process-inside/image

## Шаг 3. Свойства процесса и процессорное время
* **Процессорное время (Total Time):** `0:00:00.015` (Kernel Time: `0:00:00.000`, User Time: `0:00:00.015`).
* **Почему процессорное время не растёт в ожидании Enter:** процесс заблокирован на системном вызове чтения ввода (`getchar`) и переведён планировщиком ОС в состояние ожидания. Пока не нажата клавиша, процесс не получает процессорного времени.

labs/01-process-inside/image

## Шаг 4. Дескрипторы процесса (Handles)
* **Количество открытых дескрипторов:** `51`.
* **Куда ведут дескрипторы ввода и вывода:** к драйверу консоли Windows (`\Device\ConDrv`). Через него `printf` выводит текст в окно терминала, а `getchar` читает нажатие клавиш.

## Шаг 5. Загруженные библиотеки (DLL)
* **Системные библиотеки процесса:** `kernel32.dll`, `KernelBase.dll`, `ntdll.dll`.

## Шаг 6. Принудительное завершение процесса
* **Код завершения (`%ERRORLEVEL%`):** `-1978334964`.
* **Почему код не равен нулю:** процесс был принудительно прерван извне через Диспетчер задач с помощью `TerminateProcess`, поэтому нормального завершения с кодом `0` не произошло.

## Шаг 7. Процесс на Python
* **PID процесса `python.exe`:** `1300`.
* **Занимаемая память:** `4.2 мб` — примерно в `14` раз больше, чем у программы на C. Это объясняется тем, что в память загружается сам интерпретатор Python и его стандартные модули.
