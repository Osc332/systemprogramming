# Лабораторная работа 2. Отладчик

## Среда выполнения
* **Операционная система:** Windows 11 (x64).
* **Компилятор:** Microsoft (R) C/C++ Optimizing Compiler версии 19.44.35219 для x64.
* **Отладчик:** Visual Studio (`cppvsdbg`).

## Шаг 1. Сборка с отладочной информацией и запуск
* **Команда сборки:** `cl /Zi debug.c`.
* **Вывод программы:** `agent: total=6 area=12`.

![Сборка и запуск]

## Шаг 2. Установка точки останова
* **Строка остановки:** строка `15` (`p.x = 3; p.y = 4;`).

![Точка останова]

## Шаг 3. Остановка на точке останова и значения переменных
* **Значения до выполнения строки 15:** `p.x = 0`, `p.y = 0`, `total = 138414080`. Значение `total` является «мусорным», потому что переменная ещё не инициализирована и лежит в неинициализированной памяти на стеке.
* **Почему пропущена строка 16:** строка 16 пустая и не содержит исполняемых инструкций в машинном коде, поэтому отладчик сразу переходит к следующей исполняемой строке `17`.

![Остановка на точке]

## Шаг 4. Массив символов `name` в памяти
* **Первый символ (`name[0]`):** `'a'` (ASCII-код `97`).
* **Завершающий ноль (`'\0'`):** находится в ячейке `name[5]` (код `0`).

![Массив name]

## Шаг 5. Наблюдение за циклом (Watch)
* **Значения на втором проходе цикла:** `i = 2`, `total = 1` до выполнения `total += i;`; после шага `total = 3`.

![Цикл в Watch]

## Шаг 6. Вход в функцию `area` и стек вызовов (Call Stack)
* **Количество строк в стеке вызовов:** `2` пользовательские функции: сверху `debug.exe!area(Point p)`, ниже `debug.exe!main()`.
* **Значения параметров внутри `area`:** передана копия структуры `p = {x = 3, y = 4}`.

![Стек вызовов]

## Шаг 7. Дизассемблированный код (Disassembly View)
* **Инструкция умножения:** `imul`; в машинном коде — `0F AF 44 24 24` (`imul eax, dword ptr [rsp+24h]`).

![Дизассемблированный код]

## Шаг 8. Завершение программы
* **Итоговый вывод в терминале:** `agent: total=6 area=12`.
* **Код завершения:** `0`.

![Завершение программы]
