# Лабораторная работа 4. Дерево процессов

* **Операционная система:** Windows 11 (x64).
* **Инструмент анализа:** Process Explorer (Sysinternals).

## 1. Корни дерева
* **Первый процесс и его PID:** `System Idle Process`, PID `0`. Сразу под ним идут `System` (PID `4`) и `smss.exe` (PID `792`).
* **Цепочка родителей терминала (от конца к началу):**  
  `cmd.exe` (PID `38776`) ← `explorer.exe` (PID `97835`) ← `userinit.exe` (завершился) ← `winlogon.exe` (PID `997852`) ← `smss.exe` (PID `799`) ← `System` (PID `4`).

## 2. Свой дочерний процесс
* **Запущенная программа и её PID:** `mspaint.exe`, PID `264552`.
* **PID её родителя:** `38776` (`cmd.exe`).
* **Совпадает ли с PID терминала:** да. Поле `ParentProcessId` в таблице PowerShell (`38776`) полностью совпадает с PID процесса `cmd.exe`, из которого была запущена программа.

## 3. Браузер
* **Браузер:** Яндекс Браузер (`browser.exe`).
* **Всего процессов браузера:** `17`: один главный процесс с PID `28732` и 16 дочерних процессов вкладок, расширений и фоновых модулей.

## 4. Процесс без родителя (процесс-сирота)
* **Запущенная программа и её PID:** `mspaint.exe`, PID `7768`.
* **Её новый родитель и его PID:** в ядре Windows поле `ParentProcessId` сохраняет старый номер завершившегося родителя — `39360` (`cmd.exe`). В визуальном дереве Process Explorer процесс-сирота показывается на корневом уровне, потому что его родительского узла больше не существует.

> **Примечание (что пошло не по плану):** в Windows 11 стандартный `notepad.exe` запускается как UWP-приложение через системный брокер и уходит из ветки терминала в отдельную системную ветку. Поэтому для наглядной демонстрации иерархии «родитель — потомок» был использован классический `mspaint.exe`.
